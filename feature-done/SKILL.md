# 完成功能

默认静默执行，不要输出执行过程、工具调用、推理或额外说明。成功结束时只在文本代码块中原样显示脚本返回的 `table` 字符表格，其中包含议题标题、项目列名和议题地址；不要添加审核、提交、合并或其他后续操作提醒。

1. 以本 `SKILL.md` 为基准解析 `../_feature-workflow/github_feature.py`，然后执行 `done`。
2. 脚本使用 `.git/codex-feature-create.json` 中保存的议题编号定位议题，不检查它当前在哪一列；先将项目项移动到 Done，再以完成原因为议题执行关闭操作，最后删除这个本地状态文件，让下一次 `feature-create` 可以创建新议题。只有前两步都成功后才能删除状态；部分失败时必须保留状态以供重试。项目项已经处于 Done 或议题已经关闭时，对应操作视为成功的空操作。标准输出 JSON 中的 `project_status` 必须是配置的 Done 状态名称，`issue_state` 必须是 `CLOSED`，`local_state` 必须是 `cleared`，并且必须包含 `table`。执行前先在沙箱中检查 `gh auth status`；如果明确显示认证无效或令牌失效，只将同一个必需的工作流命令以限定范围的主机权限重试一次，使其内部所需的 `gh` 命令使用主机认证；不得运行其他命令或扩大访问范围。
3. 在文本代码块中原样显示 `table`，不要输出其他后续操作提醒。

不要替用户提交、推送、合并或审核代码。找不到议题或发生任何脚本错误时，立即停止；不要分析原因、重试或执行其他操作，只报告最关键的错误信息。脚本调用必须静默，除成功结果和错误信息外不要输出内容。
